# Phase 1 — controller rulings

Decisions taken during execution of `docs/superpowers/plans/2026-10-24-sentinel-phase-0-1-core.md`, where the plan was silent, was wrong, or conflicted with the spec. The spec (`docs/superpowers/specs/2026-10-24-project-sentinel-design.md`) was the binding authority throughout.

Each entry records what was decided, why, and what it costs if the decision was wrong. **Phase 2 should read this before revisiting any of it** — several rulings exist specifically to stop a later change from undoing a verified property. R50 is the clearest example: it rejects a reporting improvement because implementing it would reintroduce a race the walker was built to eliminate.

65 rulings in total.

- **Four corrected defects in the plan itself:** R34 (a wildcard token no registry entry uses), R39 (a self-contradicting fingerprint test), R54 (a test demanding a refusal the spec never promised), and R49 (a condition I attached to R46 and then failed to enforce).
- **Three corrected earlier rulings of mine:** R31 (R29's rationale was false for out-of-tree symlinks), R59 (R-era strictness on the attestation word was a spelling test, not a consent test), R51 (clone deletion on a read-only query broke a legitimate workflow).
- **Two were promotions of reviewer-rated Minors** on spec grounds (R9, R10), after which the process was corrected to route Minors to the deferred list instead.

The full text of each ruling follows, in the order made. The deferred findings they reference are in `docs/PHASE-1-DEFERRED.md`.

## Ruling R31: AMENDING MY OWN RULING R29. I upheld skipping all symlinks on the stated basis that it "costs no coverage, because a file or directory a symlink points at is still walked at its real location". The reviewer checked exactly that claim at my request and it is FALSE for a symlink whose real location lies outside the walk — the common monorepo shape where packages/shared points at ../../shared. Such a directory's contents are scanned nowhere. The behaviour stays: following it would read outside root, which the scope lock forbids, so skipping is correct and the reviewer agrees. What was wrong was my rationale, and a wrong rationale is what stops someone revisiting this later. Two consequences. First, the rationale is corrected here: skipping all symlinks is right because following them escapes the root, and it DOES cost coverage for out-of-tree link targets, which is an accepted and recorded limitation rather than a free win. Second, `not-regular` is the wrong word for "a directory of real source we declined to scope" — a report reader cannot distinguish that from a FIFO, and in a symlink-heavy monorepo a large fraction of the real source could be omitted under a label implying it was never source at all. A distinct `symlink` reason value is therefore added, making NINE skip reasons. Carried obligation: Task 11 must render nine reasons, and must make the symlink case legible as declined-scope rather than as an unreadable oddity. Cost if wrong: one more enum value to render; against it, a monorepo user who cannot tell that half their code went unscanned.

## Ruling R33: the branch must be SQUASH-merged, not merge-committed, and this is a constraint on how the phase finishes rather than a preference. The 1,048,603-byte filler fixture was committed in 1efa51b and deleted in 16a9c8d. Deleting a file does not remove its blob from history: an ordinary merge preserves both commits' parentage, so the megabyte would enter the default branch's history permanently and every future clone would pay for it. A squash merge produces a single commit carrying only the final tree, and the blob never reaches the default branch. Recorded here because the decision gets made at finishing-a-development-branch, long after the reason is visible, and because it is the kind of detail that is free to honour now and impossible to undo later. Cost if wrong: a permanent megabyte in a security tool's public repository, in a project whose credibility rests partly on its own hygiene.

## Ruling R37: the reviewer found a silent miss I had not considered, and it is the most consequential finding of this task. Class matching is exact, so a `sql-injection` query NEVER selects `cross-file-taint-source-to-sink`, whose declared classes are `taint-flow` and `injection`; `entrypoint-reachability-under-auth-state` (class `reachability`) is in the same position. These are the two L2 dataflow techniques — the deepest and most valuable entries in the registry, the ones that distinguish Sentinel from a pattern scanner — and they fire only if a caller already knows to ask for those exact class names. A caller reasoning from a concrete finding class, which is the natural way to query, gets the shallow entries and silently misses the deep ones. Fixed in this round, but deliberately NOT by adding a class hierarchy or synonym expansion: that is a ranking-semantics design decision belonging to a phase with real usage data behind it, and inventing a taxonomy now would be exactly the speculative complexity this plan has avoided throughout. Instead the behaviour is made explicit and tested, so a caller cannot be unaware of it, and Task 12 inherits the obligation to query cross-cutting classes alongside concrete ones. Cost if wrong: Sentinel's two deepest techniques stay opt-in rather than automatic for one more phase, which is honest-but-thin rather than silently-broken.

## Ruling R40: the three Important findings and four of the Minors are dispatched as ONE fix round under a single principle — the findings store must not trust its callers — rather than as seven separate items. ## Ruling R55: the reviewer escalated a design question and I am accepting its proposal, because the current behaviour is a gate that cannot trip.
